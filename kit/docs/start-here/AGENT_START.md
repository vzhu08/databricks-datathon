# Start with the requested outcome

1. Read the request and root AGENTS.md. Inspect the target branch, diff, framework, package manager, runtime and scoped instruction files.
2. Choose **create** for a new app or **plan/add** for an existing npm/Next App Router app. Other frameworks use reviewed portable source integration.
3. Search `npm run kit -- search "task words"` or read [CATALOG](../../CATALOG.md). Examples: analyze PDFs → documents + retrieval + extraction + exports; voice interface → voice (+ jobs if long processing); recommend to a group → recommendations + realtime; add auth → supabase; run a long job → jobs.
4. `npm run kit -- inspect <id>` reveals exact source, minimalRead, environment, dependencies and checks. Read those files, not the entire repository.
5. Plan the dependency closure. Review conflicts, routes, schema and assets. Keep live integrations disabled until explicitly configured.
6. Create or adopt; run doctor, local checks and a real user flow. Inspect generated instructions and test outside the original checkout.
7. Report what works, actual evidence, limits and next action. Fixture tests are not live verification. Read [status](../implementation/STATUS.md) only when maintaining this toolkit.

For implementation tasks use the [task card](../templates/TASK_CARD.md), shared schemas/fixtures and [collaboration rules](../playbooks/COLLABORATION.md). Root rules maintain the toolkit; docs/templates become project documents; docs/resources is reference material.
