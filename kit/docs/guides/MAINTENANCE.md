# Maintenance checklist

At each event kickoff and before a tagged kit release: install from lockfiles, read dependency advisories, run catalog/docs validation and all local examples, regenerate at least one minimal and one multi-module project outside the kit, and test existing-project adoption. Review upstream SDK changes and model IDs against official docs, then update exact versions and local adapter contracts together.

Record the date and account prerequisites for live re-verification; old credentialed success does not promise present availability. Refresh callback URLs, RLS/storage policies, timeouts, upload limits and price tables. Delete obsolete API recommendations rather than adding another unsupported adapter. Check that examples still compose canonical source and that generated docs only reference exported files.

Review event feedback: setup delays, shared-file contention, failed boundaries, misleading UI labels and weak evaluation cases. Promote only reusable improvements with tests and provenance. Keep scope small enough for the team to inspect; do not maximize module/agent/file counts.
