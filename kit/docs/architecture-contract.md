# Implementation contract for module authors

Canonical module path modules/<id>. Runtime imports from ../../../packages/contracts/src/index and ../../../packages/runtime/src/index (no file extension) preserve layout on export. No dependencies on unrelated module scopes. Use module.json matching catalog/manifest.schema.ts. Every path in a manifest is repository-relative, including source, entrypoints, exports, minimalRead, contracts, examples, fixtures, integration assets/migrations. Exports normally ["modules/<id>"]. Put npm dependencies in packages with exact versions from root package.json; root lead owns installation and lockfiles. Put test dependencies only in root devDependencies. Checks use `npx vitest run modules/<id>/tests`; runnable examples `npx tsx modules/<id>/examples/demo.ts`. Own module README, fixtures, tests and examples. Docs references should be official URLs or actual files in your export closure. Live checks not run unless explicitly authorized. Tests import vitest; root tsconfig is strict. Do not import a server entry from browser code.

Shared document fields: id, filename, mimeType, hash, text, segments[{id,start,end,page?,section?,row?}], metadata. Citation: documentId, segmentId?, start, end, quote, label?. All offsets UTF-16 code units and end-exclusive. Shared exports include DocumentSchema, validateDocument, NormalizedDocument, CitationSchema, validateCitation, JobSchema, Job, ApiErrorSchema, ModeSchema, transformText, KitError, BoundedCache, httpJson, requireEnv. Add module-specific schemas within your scope.

Represent current local test evidence accurately; verification.record points at the module README until lead supplies final report. verification.exported="not run"; verification.live="not run — requires operator test credentials and authorization". No root edits from task branches.
