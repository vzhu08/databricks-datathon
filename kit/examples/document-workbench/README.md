# Document workbench

Run `npm run dev:showcase`, visit http://localhost:3001/document. Or generate `npm run kit -- create /tmp/document-demo --starter document`, install and run it independently, then visit /kit. Upload → bounded normalization → labeled-field extraction/lexical retrieval → exact source highlighting → review → CSV/PDF export. Sample: community-garden.txt, synthetic original data. Empty/malformed uploads show retryable UI; an absent labeled field is missing rather than fabricated. PDF/DOCX parsing is server-only. OCR requires the optional Python service documented in documents. For model-backed output, explicitly configure the AI adapter and validate output with extraction's validator; no live adapter is silently enabled. Browser smoke covers sample, upload, evidence, review and report download.

For the optional native OCR path, select document-python, install its OCR extra and Tesseract, and set KIT_OCR_ENABLED=true plus absolute KIT_OCR_PYTHON/KIT_OCR_WORKER paths on the web server. The route imposes a 10 MB upload bound, 15-second body deadline and 60-second worker timeout. Native OCR remains an explicit prerequisite; absent configuration returns OCR_REQUIRED. The document-python recipe also mounts a visible contract-compatible FastAPI transformation at /api/kit/python; start the separate service before using it.

A local share deliberately publishes the reviewed summary and original quotes to holders of its token on this server. It expires after one hour, supports revocation, and is process-memory only. Unsupported human edits remain labeled in CSV, PDF and shared output. PDF's base font replaces unsupported visible glyphs; exact Unicode provenance is attached as evidence.json.
