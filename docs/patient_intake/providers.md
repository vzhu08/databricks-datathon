## Engineering handoff

`providers.transport.Transport` performs one TLS JSON exchange against a server-supplied host, operation and headers. A process shares one transport and its non-renewing attempt quota. Each encounter supplies a shared physical-attempt budget across turns. Configuration defaults to zero physical attempts. The service must separately reserve logical turns and coordinate deployment quotas across replicas/restarts. A deadline bounds the caller wait. A slow exchange retains a concurrency slot until it exits. No automatic retry occurs, including when the vendor may have accepted a timed-out request.

A successful `received` result contains an untrusted JSON object for the selected adapter to validate. Unmatched evidence, unknown answers, missing recommendations, unrepresentable questions and permanent termination need distinct handling at the adapter/runtime boundary. Only validated provider output may become clinical guidance. Tests inject invented replies into the exchange and never select a provider.

### Optional MGP candidate

The default-disabled candidate implements the documented Platform Triage survey exchange for an existing server-owned survey. It presents supported single and multiple choice questions, sends only selected vendor IDs, consumes each opaque continuation before the write and verifies the same survey is completed before requesting the evidence assessment. Vendor triage text and allowed cause labels are bounded and remain preliminary. Emergency levels and consultation within 24 hours carry no ordinary navigation. An empty list of possible causes with no urgent triage returns unsupported. [Question exchange](https://developer.infermedica.com/documentation/platform-api/build-your-solution/navigating-question-flows/) · [Evidence assessment](https://developer.infermedica.com/documentation/platform-api/build-your-solution/fetching-results/)

The runtime must bind one candidate to one consented encounter, survey and evidence revision, and pass the same physical attempt budget through all turns. The sandbox session shares its quota and cooldown across encounters. The application does not configure either component. No authenticated request has been made.

| Final 204 | After an answer, verify the same Triage survey is completed before fetching its assessment. An empty first read cannot establish completion. |

Transport projects only four validated numeric rate fields. The same process transport withholds new requests after a 429 or an explicit remaining quota of zero. Cooldown lasts at least 60 seconds and honors longer supplied delays. Existing in-flight requests can finish. Rate limiting does not spend an additional attempt on a blocked request. Authorization failures, rate limits and local attempt exhaustion have separate status codes. A bare Platform 403 cannot distinguish a denied permission from a monthly limit. Obtain a stable discriminator from the provisioned API before mapping that case. Process restarts or multiple replicas require separate deployment quota coordination. [Platform API FAQ](https://developer.infermedica.com/documentation/platform-api/faq/)

### Version 2 engineering binding

The opt-in `OwnedMgpSurvey` factory uses M's owned-provider mode. Each instance reserves one slot in O's process-owned mailbox before creation. It admits and settles each user, patient and survey create separately. A reset during transport retires the reservation immediately. A late verified ID joins the cleanup obligation, and a missing ID after uncertain delivery remains unresolved. Run `dispose_claim` with a separate authenticated cleanup session and protected attempt budget. Acknowledged disposal removes only the verified prefix of survey, patient and user references. Scheduling, recovery after process loss, hosting and provider-specific retention remain deployment decisions.

`MgpSurveyV2` issues the approved optional, per-item and quantity forms. Clinical text reconciliation and unit-specific precision/bounds come from trusted server bindings. An age must be an integer. Missing duration precision or limits withhold the question. Each group-multiple item retains its own offered polarity labels. An explicit group-single skip submits unknown for every item. Ordinary optional skips submit null. A recognized non-emergency stop can display separately supplied provider-approved text.

The catalog binding accepts a complete, context-matched local source with ID, edition and at most 16 items. Each issuance uses fresh opaque option handles. Incomplete, unconfigured and oversized catalogs withhold the question. A full symptom catalog/picker, multi-page selection, vendor access and extraction remain unverified. No patient-facing configuration selects the adapter. [Approved contract and owner assignments](https://github.com/vzhu08/databricks-datathon/issues/223#issuecomment-7076496362)
